﻿﻿﻿﻿﻿﻿﻿# 兵种数据汇总（平衡调整后，2026-11）

> 数据来源：`src/data/config.js`（基础属性 / 品级倍率 / 射程 / 移速 / 攻击间隔 / 小队编制）、`src/data/traits.js`（战法倍率）、`src/core/arena.js`（小队人数、连射与伤害结算）。
> 随时用 `node tools/troop-table.mjs` 重新生成表；用 `node tools/duel.mjs` 跑同人数对局验证品级阶梯。
>
> 口径：
> - 成长率（所有兵种统一）：血 `+28%/级`、攻 `+25%/级`、防 `+18%/级` → 1 级到 10 级约 ×3.52 / ×3.25 / ×2.62
> - 品级倍率只放大「1 级基础值」：稀有 ×1.35、史诗 ×1.85、传奇 ×2.85
> - `队血` = 单兵血量 × 小队人数；`队秒伤` = 单兵攻击 ÷ 间隔 × 人数 × 战法常驻倍率（含元戎连射的平均节奏；不含克制、冲锋/突刺、毒伤）
> - `战力` = 队血 + 队秒伤 × 3 + 防御换算 × 2（含毒伤），就是布阵页「我方战力 / 敌方战力」、开战顶栏「总战力 我方 … · 敌方 …」与胜利页「本局最佳」共用的同一口径
> - **弓箭平衡（最新）**：弓兵线恢复原状（不再 ×0.5）；白马义从单独保留 **80% 伤害**（`dealtMult: 0.8`），射程 **18 格（16 格开火）**
> - **盾兵（本轮）**：除陷阵营外，盾兵本体 Lv1 `hp112 / atk12`（原 100/18）；先登 / 藤甲随本体一起变厚，藤甲再叠 `hp×1.1 / atk×0.8`；陷阵营用 `statMult` 抵消回原值（285/51.3）
> - **穿甲（本轮）**：大戟士、元戎弩士 `armorPen = 0.30`，结算 `有效护甲 = 护甲 × 0.70`，只乘一次，不再与其他穿甲重复叠算
> - **大戟士秒伤（1.2.5）**：「重甲摧锋」增伤由 **+40%→+90%（×1.4~1.9）下调为 +10%→+40%（×1.10~1.40）**，只砍大戟士；青州兵 / 白毦兵不变
> - 远程兵（弓兵线 + 白马义从骑射）走路停在「射程 - 2 格」（`CONFIG.combat.engageGap`）再开火：弓兵线射程 14 → 12 格开火（元戎 20 → 18），白马骑射 18 → 16
> - 克制环：盾 → 弓 → 枪 → 骑 → 盾（克制 ×1.1，被克制 ×0.9）

## 五、平衡目标与验证

目标（单兵口径）：**1 级传奇 ≈ 3 级史诗 ≈ 5~7 级稀有 ≈ 8 级普通**。

`node tools/duel.mjs` 跑真实斗技场 AI（同人数 4v4，每条兵线）：

| 对局 | 结果 |
| --- | --- |
| 大戟士 / 陷阵营 / 无当飞军 / 虎豹骑 Lv1 vs 同线史诗 Lv3 | **2/5 / 5/5 / 0/5 / 0/5**（白马 18 格骑射先手、元戎 16 格先手；同人数下远程先手优势很大） |
| 四条传奇 Lv1 vs 同线稀有 Lv5 | 0/5 / 5/5 / 0/5 / 0/5（青州 5→10 人、青竹 4→8 人，人数优势明显） |
| 四条传奇 Lv1 vs 同线稀有 Lv7 | 0/5 / 2/5 / 0/5 / 0/5（人数差继续拉大） |
| 四条传奇 Lv1 vs 同线普通 Lv7 / Lv8 | 全胜 |
| 四条稀有 Lv1 vs 同线史诗 Lv1 | 稀有 0/5（史诗全胜） |

> 最新 `duel` 显示「1 级传奇 vs 3 级史诗」不再是稳定 5/5：白马 18 格骑射、元戎 16 格连弩、青州/青竹多人编制都会在**同人数 4v4**里形成先手或人数优势。这是「兵种定位 + 射程/编制」的结果，不是单纯品级倍率；跨兵种平衡请以 `docs/troop_data_table.html` 的队秒伤/战力与实战编队为准。

> 实际编制下（不强制同人数）会有差异：史诗 Lv3 的小队已经多 1 个兵（Lv3/+1 增员），所以「1 级传奇 vs 3 级史诗」的小队总量并不总是赢；青州兵 5→10、青竹 4→8 的人海也会在人数上占便宜——这是「人多」的设计身份，单兵强度仍然遵守上面的阶梯。

本题外话：大戟士的「重甲摧锋」原为 +40%→+90%，队秒伤一度到同线普通兵的 4.0~5.4 倍；**1.2.5 已砍到 +10%→+40%（≈1.4 档）**，回落到 3.2~4.0 倍，与其他传奇（2.85 档 + 常驻增伤）的差距收进合理区间。若以后还要压，直接调 `traits.js` 里 `lerp(0.10, 0.40, lv)` 的上下界即可。

### 演武（200 关：1~50 手写、51~200 生成）难度曲线（本轮重设）

> 下面列出的具体节点是**前 25 关**的手写档位；第 51~200 关由 `trials.js` 按 `statMult` 递推生成，逐关数值请用 `node tools/sim.mjs` / 游戏内战前信息核对。

- 传奇卡统一封顶 **Lv5**（前 5 关 ≤Lv4）；非传奇按关卡继续成长到 Lv10。
- 小队数从 3~9 提升到 **4~12**，用数量 + 稀有/史诗占比承担难度，不再靠高等级传奇卡关。
- 关键节点（敌军战力，当前盾兵数值口径）：第 1 关 5,615（4 队 Lv3）/ 第 5 关 9,528（6 队 Lv3，首个传奇 Lv3）/ 第 10 关 21,124（7 队 Lv5~6）/ 第 15 关 25,895（8 队 Lv5~8）/ 第 20 关 37,962（9 队 Lv5~8）/ 第 25 关 54,812（12 队 Lv5~10，传奇仍封顶 Lv5）。25 关合计 645,542（旧版约 679,647）；旧版同节点约 5,067 / 13,732 / 21,142 / 25,936 / 36,364 / 75,166（旧版第 25 关传奇也吃 Lv10，被高等级传奇卡关）。

经济：首通铜钱 = `(30 + 6×关号) × 80%`（整体 −20%）：第 1 关 28 / 第 50 关 264 / 第 100 关 504 / 第 200 关 984 / 第 400 关 1,944。默认 `node tools/sim.mjs`（1 seed + 每 20 关抽样）在 1 小时挂机假设下本次卡在**第 219 关**（347 场，含 120 场同一关重试，282.5 秒）；`--full` 逐关全量的 seed 1 跑 427 场卡在**第 189 关**（277.4 秒），说明 180~220 段是当前的真实卡点。单场模拟时长 18.7 秒是第 600 关参考军实测（口径：`simulateArena` 返回的 `result.time`，固定 1/30 秒步长、200 秒上限，见 `docs/playtest-report.md` 3.1）；旧文档的 22.0~25.6 秒作废。2600 关全量按 0.6~0.7 秒/场估算约 25~35 分钟/seed。
