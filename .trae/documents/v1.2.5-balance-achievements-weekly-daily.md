# 1.2.5 版本实现计划：平衡修复 + 成就系统 + 周常挑战 + 每日挑战

## Context

1.2.4 全面体检发现两个数值问题（大戟士秒伤离谱、300 关起敌方器械顶替小队造成战力凹点），同时内容盘点发现 250 关后解锁空窗、缺少长线留存钩子。用户要求 1.2.5 完成：①两项平衡修复 ②成就系统 ③周常挑战（5 档×10 小关、每周积分选兵）④每日挑战（30 关、敌方英雄带队），完成后上传体验版 1.2.5。

### 已确认的口径（用户拍板）
1. **只砍大戟士**：重甲摧锋 dealtMult Lv10 1.9→1.4；青州兵、白毦兵不动。
2. **补回 25 小队**：敌方器械不再顶替小队（25 队 + 1 器械）。
3. **周常积分每周重置**：每周固定积分重新买兵种等级，下周归零。
4. **每日挑战共 30 关**：前 12 关单英雄（史诗→传奇），后 18 关 2~3 英雄，最难对标主线 2000 关。开放方式采用「30 关顺序解锁常开 + 首通永久奖 + 每日前 3 胜小额奖」（最少状态、最少 bug 面）。

## 关键默认值

| 项 | 值 |
|---|---|
| 大戟 dealtMult | `1 + lerp(0.10, 0.40, lv)`（Lv1 +10% / Lv10 +40% → 队秒伤 3.14→3.99，仍高于其他传奇 2.85）；`statMult 0.88` 不动 |
| 周常积分预算 | 1600 / 周；成本 `base{common16, rare24, epic34, legendary48} × 1.45^(lv-1)` |
| 5 档难度倍率 | 0.90 / 1.12 / 1.30 / 1.48 / 1.68（× draft 战力上限，档内每关 +2%） |
| 档位敌等级锚点 | 350 / 550 / 800 / 1200 / 1700；敌方器械仅第 4、5 档出 |
| 周常扫荡 | 已首通关每日限 6 次，发该关首通铜钱 60%，无宝箱 |
| 每日 30 关锚点 | `engineStageFor('daily', stage) = 300 + round((stage-1)×1700/29)`，第 30 关 = 2000；英雄数 1~12 单将 / 13~24 双将 / 25~30 三将，hpMult 3→12 |
| 成就首批 | 约 15 条 × 2~3 档（战斗/图鉴/养成/挑战/经济），奖励铜钱+宝箱 |

## 实施顺序

### P1 平衡修复（最小、先落地）
- daji dealtMult → `1 + lerp(0.10, 0.40, lv)`；同步 test.mjs 战法文案断言（'40%''90%'→'10%''40%'）、troop-balance.md 表格。
- levels.js L309-317：删掉 `placed.filter(i !== idx)`，器械改为追加（引擎走 stancePoint 独立坐标，不占 25 格；heroBattle/斩将已有「12 队+器械」先例）。同步 test.mjs `unitCount===25→26`（L266/L305 附近）、`===24→25`（L4603 附近）与 docs 中「器械替换阵位」注释。

### P2 每日挑战（复用最多）
- `dailyBattleDef(stage)`：anchor = `engineStageFor('daily', stage)` → 复用 `levelDef(anchor)` 骨架；末 K 队替换为英雄小队（K=1/2/3 分段、史诗先传奇后、hpMult 3→12）；`def.heroBattle` 走英雄战 UI 但**不写 heroBattleCleared**。
- 流程：DailyChallengeScreen → `DeployScreen(g, anchor, {dailyChallenge:{stage, def}})` → BattleScreen 结算：首通 `state.dailyChallenge.progress[stage-1]=1` + 铜钱 800→20000 阶梯 + 宝箱；重复胜利计 `state.daily.dailyWins[dateKey]`（前 3 胜 500 铜钱+木箱）。

### P3 周常挑战（最大）
- `weekKey()`（ISO 年-周，北京时间）；`ensureWeekly` 换 key 整域重建（积分/购买/进度归零）。
- 存档域 `state.weekly = { key, points, roster:[{troop,level}], form:[25槽], tier, cleared[5×10], firstClear, sweepDate, sweepCount }`。
- `draftCapPower(state)`：对已解锁兵种按性价比贪心买满 1600 积分 → 理论 draft 战力上限（不含英雄/器械/兵书）。
- `weeklyLevelDef(state, tier, stage)`：`target = draftCap × TIER_MULT[tier] × (1+0.02×(stage-1))`，生成敌阵容使 ΣtroopPower ≈ target ±10%；tier≥4 附 `enemyEngineFor(anchor, true)`。难度差额只能靠玩家真实英雄/器械/兵书补 → 正好实现用户要的五档门槛。
- 战斗：WeeklyShop 买等级 → `DeployScreen(g, tierAnchor[tier], {draft:{roster, form}})`（英雄卡/器械面板=真实进度）→ `BattleScreen(..., {weekly:{tier,stage}, playerSquads:draftSquads})`。胜：`cleared[tier-1]` + 首通奖励（档位递增，每档第 10 关加宝箱）+ 开扫荡。

### P4 成就
- 轻量计数器 `state.counters = {wins, battles, chestsOpened, sweeps}`：只在各结算屏构造/开箱处各加 1 行，其余进度复用现成状态（maxCleared、兵种图鉴、英雄持有、兵书、器械档位、模式进度）。
- `data/achievements.js` 每条 `{id, cat, tiers:[{n, reward}], progress(state)}`；`claim()` 经 addChest/addCoins 发放；AchievementsScreen 分类页签 + 进度条 + 领取，首页入口常显。
